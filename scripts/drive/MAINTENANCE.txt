LOOKING AFTER THIS DRIVE, AND PASSING IT ON
===========================================

This drive holds the Knowledge Arc: an offline library of trusted
practical knowledge (health, food, water, energy, making and repairing),
encyclopedias, books, courses and maps. It needs no internet. You may
have been given it, or found it; nobody needs to explain it to you. To
read it, open "1 START-HERE" at the top of the drive.

This file says how to keep the drive working, how to repair it, and how
to make copies for other people. Its knowledge lasts as long as copies
exist, so please make copies and pass them on.

Part 1 needs no internet and nothing installed. Part 2 is only for when
the internet works.

Words used here:
  drive     the USB stick, memory card or disk that holds the library
  folder    a place on the drive that holds files (written arc > system:
            open the folder arc, then the folder system inside it)
  exFAT     the way a drive must be prepared ("formatted") to hold this
            library. Many sticks and cards come as FAT32 instead, which
            cannot hold files bigger than 4 GB. See step 4.
  terminal  on a Mac or Linux, the program where you type commands
            (Mac: Applications > Utilities > Terminal)


PART 1: WITHOUT INTERNET
------------------------

1. OPEN IT

   - Computer: double-click "1 START-HERE". It opens in the web browser
     and lists everything by subject. The guides open right there.
   - For search and the big collections (encyclopedias, repairs, books,
     courses, maps), double-click "2 Open full library (Windows)" or
     "2 Open full library (Mac)". A small window opens: keep it open
     while you read. Linux: in a terminal, run  sh arc/open-full-library.sh
   - Android phone or tablet: see step 5.
   - More help: "1 START-HERE" > How to use.

2. CHECK IT EVERY 6 TO 12 MONTHS

   Drives left in a drawer can lose data without any sign. A regular check
   finds the damage while other copies are still good.

   - Plug the drive in. Leave it plugged in while the check runs: this also
     does an unpowered drive good.
   - Windows: open arc > system and double-click verify.bat.
   - Mac or Linux: in a terminal, type
         sh /path/to/the/drive/arc/system/verify.sh
     (on a Mac you can type "sh " and then drag verify.sh into the window).
   - On a big drive the check takes an hour or more. Wait for the last line:
       ALL GOOD ...   nothing to do.
       PROBLEM ...    it lists the damaged or missing files: see step 3.
   - Then open a few things by hand: 1 START-HERE, one guide, and the
     full library. If they open, the drive is usable.
   - Write the date and the result on the drive's card or label.

3. REPAIR A DAMAGED FILE FROM ANOTHER COPY

   - You need another copy of the same version. The first line of
     arc/system/VERSION.txt ("Built: ...") must be the same on both drives.
   - For each file the check listed, copy it from the good drive to the
     same folder on the damaged drive, replacing the damaged one.
   - Run the check again on the repaired drive until it says ALL GOOD.
   - If arc/system/CHECKSUMS.sha256 itself is damaged, the check cannot run:
     copy the whole arc/system folder from a good copy of the same version.
   - If many files are damaged, or the same drive is damaged again at the
     next check, the drive is failing: copy it onto a new drive (step 4).
   - No copy of the same version? A file from another version may still
     work, but the check will keep listing it. Every guide (PDF) is an
     ordinary file and can be read on its own.

4. MAKE A COPY (TO PASS ON, OR TO REPLACE A FAILING DRIVE)

   a) Find a drive big enough. The size of this library is on the line
      "Items: ..." in arc/system/VERSION.txt. The new drive must be bigger
      than that, with a little room to spare.

   b) Check how the new drive is formatted. It must be exFAT.
      - Windows: in File Explorer, right-click the drive, Properties, and
        read "File system".
      - Mac: select the drive in the Finder, File > Get Info, and read
        "Format".
      If it says FAT32 (or MS-DOS FAT), copying stops at the first big file
      with an error such as "file too large". Format it as exFAT first.
      Formatting ERASES everything on the new drive.
      - Windows: in File Explorer, right-click the new drive, Format...,
        File system: exFAT, then Start.
      - Mac: Disk Utility, select the new drive, Erase, Format: ExFAT,
        Scheme: GUID Partition Map, then Erase.
      - Linux: use the Disks program (Format Partition, type exFAT).

   c) Open this drive, select everything at its top level (1 START-HERE,
      the "2 Open full library" files and the folder arc), and copy it to
      the new drive. This can take several hours. Don't unplug either drive
      until it has finished.

   d) Run the check (step 2) ON THE NEW DRIVE. Only trust it once it says
      ALL GOOD.

   e) Print the card (1 START-HERE > Keep it alive > The card to print),
      stick its bottom strip on the new drive, and keep the card with it.

   Drives wear out. Plan to replace each drive after about five years, or
   at once if it makes clicking noises, is very slow, or fails a check twice.

5. PUT IT ON AN ANDROID PHONE OR TABLET

   The smallest edition (the pocket edition, about 24 GB) is made for
   phones. Which edition this is: "1 START-HERE" > About > Editions. If
   this drive is a bigger edition, first make a pocket copy (step 6).

   a) Install the Kiwix app. On the drive it is in arc > software > android
      (the file starting "kiwix"). Open it from the phone's Files app. If
      the phone refuses, allow "install unknown apps" for the Files app in
      the phone's settings, then try again.

   b) Either read it from the drive (a USB stick with a phone connector, or
      a memory card in the phone), or copy it onto the phone:
      - Connect the phone to a computer with a USB cable and choose "File
        transfer" on the phone.
      - Copy everything at the top of this drive into a new folder on the
        phone (for example "Knowledge Arc" inside Download).
      - Memory cards of 32 GB or less usually come as FAT32, which cannot
        hold the biggest file (Wikipedia). Format the card as exFAT on a
        computer first (step 4b). If the phone then says the card is not
        supported, copy to the phone's own storage instead.

   c) Open Kiwix and open the files ending in .zim: first
      arc > site > knowledge-arc_en_all.zim (the subjects and guides), then
      those in arc > collections.

   d) The guides (PDFs) also open from the Files app. If the phone has no
      PDF reader, install MuPDF from arc > software > android.

6. MAKE A POCKET COPY FROM A BIGGER DRIVE

   Every drive bigger than the pocket edition can make a pocket copy, with
   no internet and nothing to install: on a stick or memory card of 32 GB
   or more, for a phone or to pass on.

   a) Plug in the stick or card. It must be formatted exFAT (step 4b):
      most 32 GB sticks and cards come as FAT32, which cannot hold the
      pocket Wikipedia (5 GB). The copy refuses a FAT32 drive.
   b) Open the folder arc on this drive and double-click
        Windows:     Make a pocket copy (Windows)
        Mac:         Make a pocket copy (Mac)
        Linux:       in a terminal,  sh arc/system/make-pocket-copy.sh
   c) Type the letter (Windows) or the name (Mac, Linux) of the stick when
      asked. It copies the pocket edition, then checks every file. It can
      take an hour; you can stop it and run it again later, and it carries
      on where it stopped.
   d) "ALL GOOD" at the end means the pocket copy is ready. Then step 5.

   How it works: arc/pocket holds the pocket edition's own pages, its
   Wikipedias and the list of its files with their fingerprints. The
   rest is taken from this drive. Do not change or delete arc/pocket.
   Cutting a pocket copy by hand does not work: the website on each drive
   is made for exactly what is on it.

7. SHARE IT OVER WI-FI (ADVANCED)

   One computer can serve the full library to phones and other computers
   nearby; they read it in their web browser, with nothing to install.

   - Windows: open the folder arc and double-click
     "Share over Wi-Fi (Windows)". Mac: open arc and double-click
     "Share over Wi-Fi (Mac)". Linux: sh arc/open-full-library.sh --share
   - The window lists one or more addresses such as
     http://192.168.1.20:8642/ . On each phone, connect to the same Wi-Fi
     and type one of them in the browser. If one does not work, try the
     next.
   - The computer asks whether to let the library accept connections:
     choose Allow (on Windows, tick Private networks). Without that,
     phones cannot connect.
   - No Wi-Fi network? On most phones you can turn on the "hotspot": it
     makes a Wi-Fi network, even with no internet. Connect the computer
     and the other phones to it.
   - Anyone on that network can read the library while the window is
     open. Close the window to stop sharing. Use it only on networks you
     trust.

8. PRINT A PAPER COPY

   Paper needs no power and no screen. The whole library is far too big to
   print, so the website says what to print first: open 1 START-HERE, then
   Keep it alive > Print a paper copy. It lists, with their page counts:
   - the essentials, a few hundred pages: print these first;
   - more guides, if you have the paper and ink;
   - books worth buying printed while you still can.
   If that page does not open, the essentials are listed with their
   folders in arc > START-HERE.txt.

   To print a guide, open it and choose Print (Ctrl+P, or Cmd+P on a Mac).
   Print on both sides of the paper. Print the list too, tick each guide
   once printed, and keep the pages flat and dry, in folders or binders.

9. STORING THE DRIVES

   - Keep several copies in different places (different houses if you
     can), never all in one bag. That is the real protection.
   - Cool, dry place, away from sunlight, magnets and heaters.
   - In a padded bag or box. Hard drives (the heavier kind, which spin) can
     be damaged by a fall, especially while running.
   - Always "eject" or "safely remove" a drive before unplugging it.

10. IF SOMETHING DOES NOT WORK

   - The guides never need the full library: open 1 START-HERE.
   - If 1 START-HERE does not open, open arc > START-HERE.txt: it lists
     the same things, with their folders.
   - Keep the small library window open while you read. Closing it stops
     the library.
   - If the browser does not open by itself, type 127.0.0.1:8642 in the
     browser's address bar.
   - "Already in use", or the window closes at once: the library may still
     be running from earlier. Close every Knowledge Arc window, or restart
     the computer, and try again. Windows writes the details to the file
     knowledge-arc.log in the temporary folder (type %TEMP% in the File
     Explorer address bar to find it).
   - Mac: if macOS says the program cannot be opened, open System Settings,
     Privacy & Security, scroll down, and click "Open Anyway" for
     kiwix-serve, then double-click "2 Open full library (Mac)" again.
   - A collection marked "Could not be opened", or pages that say "Page
     isn't working": that file is probably damaged. The rest still works.
     Run the check (step 2) and repair the file (step 3).
   - The drive carries its own programs, in arc > software, for when the
     computer's own do not work:
       no web browser, or it will not show the pages: Firefox
         (Windows: arc > software > windows > firefox > firefox.exe;
          Mac: the firefox file in arc > software > mac)
       the guides (PDFs) will not open: SumatraPDF (Windows,
         arc > software > windows > sumatrapdf), MuPDF (Android)
       the full library will not start: the Kiwix reader opens the .zim
         files by itself (arc > software > windows > kiwix-desktop, or the
         kiwix files in arc > software > mac and linux)
     On a Mac, a file ending in .dmg opens as a window: double-click the
     program inside it.
   - Phone cannot see the drive at all: it may not read exFAT drives. Copy
     the library onto the phone from a computer (step 5b), or use a
     computer.

11. WHAT IS ON THIS DRIVE

   - arc/system/CATALOG.csv lists every item: what it is, who published it,
     where it came from, its licence, and who checked it. It opens in a
     spreadsheet (Excel, LibreOffice, Numbers).
   - arc/system/VERSION.txt: when this copy was built, which edition it is
     ("Selection: bundle pocket", core, standard or full), and what changed
     at each rebuild (newest first).
   - arc/system/recipe: the recipe that built this library (Part 2).
   - arc/pocket (on drives bigger than pocket): what a pocket copy needs
     beyond this drive's own files (step 6).
   - Do not add or remove files in arc/guides or arc/collections by hand:
     a removed file makes the check fail, and an added file is never
     checked or copied to other drives. Personal documents do not belong
     on this drive.


PART 2: WHILE THE INTERNET WORKS (REFRESH OR REBUILD)
-----------------------------------------------------

The library is built by a recipe: a list of every item (the catalog) and
the scripts that download, check and assemble them. A copy of the recipe
is on every drive, in arc/system/recipe. A refresh or rebuild is done on a
computer with an internet connection (and, for the full way below,
Python 3 and a big disk: the "archive", which keeps every file as
downloaded).

The easy way, for one new drive: copy the folder arc/system/recipe to
the computer, plug in an empty drive formatted exFAT, and double-click
make-arc.bat (Windows) or make-arc.command (Mac, Linux) in that copy.
It asks which drive and which edition, downloads every item straight
onto the drive, checks each one and builds the library. It is safe to
stop and run again. Nothing needs installing first: it uses the
computer's own Python if it is 3.11 or newer, and otherwise fetches a
portable Python once (25-36 MB) into the computer's own cache folder
(Windows: %LOCALAPPDATA%\knowledge-arc; Mac: ~/Library/Caches/knowledge-arc;
Linux: ~/.cache/knowledge-arc). Delete that folder afterwards to remove it.

The full way, for a master drive and many copies:

1. Copy the folder arc/system/recipe from a drive to the computer and work
   from that copy (never run it from the drive itself). Read its README.md
   and CONTRIBUTING.md first.
2. Look for newer editions: run  python scripts/scan_kiwix.py  for the
   Kiwix collections, and check the key PDFs (first aid, water) at their
   publishers. Update catalog/catalog.csv. A new edition gets the same
   checks as the first one, and the first-aid guides are re-read page by
   page (the website links to exact pages: check frontdoor/situations.csv).
3. Re-check the emergency phone numbers (frontdoor/numbers.csv) at their
   sources.
4. Download everything into the archive (every edition at once):
       python scripts/download.py --dest D:/archive --bundle all --update-catalog
5. Build a drive from the archive, choosing its edition (pocket, core,
   standard or full), with a note of what changed:
       python scripts/assemble.py --staging D:/archive --drive E:/ --bundle core --note "what changed"
   A pocket copy is built the same way:  --bundle pocket
6. Run the check on the new drive (Part 1, step 2).
7. Copy it to every other drive of the same edition, which also checks
   each copy:
       python scripts/mirror.py --master E:/ --copy F:/
8. Bring every copy up to the same version: the first line of VERSION.txt
   must match on all of them.
