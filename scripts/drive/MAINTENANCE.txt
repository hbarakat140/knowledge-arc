LOOKING AFTER THE FAMILY LIBRARY DRIVES
=======================================

For the person who looks after the drives. Part 1 needs no internet and
nothing installed. Part 2 is only for when the internet works.

There are several identical copies of this drive, kept in different places.
That is the real protection: if one copy is damaged, the others are not.
Keep them apart (different houses if you can), never all in one bag.


PART 1: WITHOUT INTERNET
------------------------

1. CHECK EACH DRIVE EVERY 6 TO 12 MONTHS

   Drives left in a drawer can lose data without any sign. A regular check
   finds the damage while the other copies are still good.

   - Plug the drive in. Leave it plugged in while the check runs: this also
     does an unpowered drive good.
   - Windows: open the folder 99_SYSTEM and double-click verify.bat.
   - Mac or Linux: open a terminal and type
         sh /path/to/the/drive/99_SYSTEM/verify.sh
     (on a Mac you can type "sh " and then drag verify.sh into the window).
   - On a big drive the check takes an hour or more. Wait for the last line:
       ALL GOOD ...   nothing to do.
       PROBLEM ...    it lists the damaged or missing files: see step 2.
   - Then open a few things by hand: START-HERE.html, one emergency PDF,
     and the library (OPEN-LIBRARY). If they open, the drive is usable.
   - Write the date and the result on the drive's label or in a notebook.

2. REPAIR A DAMAGED FILE FROM ANOTHER COPY

   - First check that the good copy is the same version: the first line of
     99_SYSTEM/VERSION.txt ("Built: ...") must be the same on both drives.
   - For each file the check listed, copy it from the good drive to the
     same folder on the damaged drive, replacing the damaged one.
   - Run the check again on the repaired drive until it says ALL GOOD.
   - If 99_SYSTEM/CHECKSUMS.sha256 itself is damaged, the check cannot run:
     copy the whole 99_SYSTEM folder from a good copy of the same version.
   - If many files are damaged, or the same drive is damaged again at the
     next check, the drive is failing: replace it (step 3).

3. MAKE A NEW COPY (REPLACE A FAILING OR LOST DRIVE)

   You need a drive at least as big as the old one, and one good copy.
   Copying everything takes several hours.

   a) Format the new drive as exFAT. This erases it.
      - Windows: in File Explorer, right-click the new drive, Format...,
        File system: exFAT, then Start.
      - Mac: Disk Utility, select the new drive, Erase, Format: ExFAT,
        Scheme: GUID Partition Map, then Erase.
   b) Open the good copy, select everything at its top level (all folders
      and files), and copy it to the new drive.
   c) Run the check (step 1) ON THE NEW DRIVE. Only trust it once it says
      ALL GOOD.
   d) Label the new drive, and put it where the old one was kept.

   Drives wear out. Plan to replace each drive after about five years, or
   at once if it makes clicking noises, is very slow, or fails a check twice.

4. STORING THE DRIVES

   - Cool, dry place, away from sunlight, magnets and heaters.
   - In a padded bag or box. Hard drives (the heavier kind, which spin) can
     be damaged by a fall, especially while running.
   - Always "eject" or "safely remove" a drive before unplugging it.
   - Keep one copy away from the house (a relative, a trusted friend).

5. IF THE LIBRARY DOES NOT OPEN (OPEN-LIBRARY)

   - The emergency guides never need it: open START-HERE.html.
   - Keep the small black window open while you read. Closing it stops the
     library.
   - If the browser does not open by itself, type 127.0.0.1:8642 in the
     browser's address bar.
   - "Already in use", or the window closes at once: the library may still
     be running from earlier. Close every Family Library window, or restart
     the computer, and try again. Windows writes the details to the file
     family-library.log in the temporary folder (type %TEMP% in the File
     Explorer address bar to find it).
   - Mac: if macOS says the program cannot be opened, open System Settings,
     Privacy & Security, scroll down, and click "Open Anyway" for
     kiwix-serve, then double-click OPEN-LIBRARY.command again.
   - A collection marked "Could not be opened" on the library's home page,
     or pages that say "Page isn't working": that file is probably damaged.
     The rest of the library still works. Run the check (step 1) and repair
     the file from another copy (step 2).
   - Android phone or tablet: the Kiwix app is in 90_SOFTWARE/android.
     Tap it in the Files app to install it; if the phone refuses, allow
     "install unknown apps" for the Files app in the phone's settings. Then
     open the .zim files on the drive from inside Kiwix. Better still,
     install it on the family's phones in advance, so it is ready.
     If the phone cannot see the drive at all, it may not read exFAT
     drives: use a laptop instead.
   - The programs are in 90_SOFTWARE. If one is damaged, the check (step 1)
     lists it: repair it like any other file (step 2).

6. WHAT IS ON THIS DRIVE

   - 99_SYSTEM/CATALOG.csv lists every item: what it is, who published it,
     where it came from, its licence, and who checked it. It opens in a
     spreadsheet (Excel, LibreOffice, Numbers).
   - 99_SYSTEM/VERSION.txt: when this copy was built, and what changed at
     each rebuild (newest first).
   - Do not add or remove files in 00_EMERGENCY, 01_LIVING or 02_KNOWLEDGE
     by hand: a removed file makes the check fail, and an added file is
     never checked or copied to the other drives. Personal documents do not
     belong on this drive.


PART 2: WHILE THE INTERNET WORKS (OPTIONAL REFRESH)
---------------------------------------------------

The drive is built by a recipe kept in a git repository (the catalog, the
download and build scripts, the front door). The person who built the drive
has it. A refresh is done on a computer with Python 3, using that recipe:

1. Get the recipe up to date (git pull) and read its CLAUDE.md and
   NEXT-SESSION.md.
2. Look for newer editions: run  python scripts/scan_kiwix.py  for the
   Kiwix collections, and check the key PDFs (first aid, water) at their
   publishers. Update catalog/catalog.csv. A new edition gets the same
   checks as the first one, and Tier 1 guides are re-read page by page
   (the front door links to exact pages: check frontdoor/situations.csv).
3. Re-check the emergency phone numbers (frontdoor/numbers.csv) at their
   sources.
4. Download into a staging folder on a big disk:
       python scripts/download.py --dest D:/staging --bundle core --update-catalog
5. Build the master drive from staging, with a note of what changed:
       python scripts/assemble.py --staging D:/staging --drive E:/ --bundle core --note "what changed"
6. Run the check on the master (Part 1, step 1).
7. Copy the master to every other drive, which also checks each copy:
       python scripts/mirror.py --master E:/ --copy F:/
8. Bring every copy up to the same version: the first line of VERSION.txt
   must match on all of them.

Use the same bundle (core, standard or full) as the drives you are
refreshing: the first lines of VERSION.txt say which one was built.
