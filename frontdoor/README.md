# The website's inputs

The arc's website is **generated** by `scripts/frontdoor.py`, which `scripts/assemble.py` calls on every build: `1 START-HERE.html` at the top of the drive, every other page in `arc/site/` (home, 11 subjects, a page per topic, shelves, For children, A to Z, How to use, Keep it alive, About), and the plain-text twin `arc/START-HERE.txt`. Never edit them on a drive by hand. They're built from the items actually placed on that drive, so they never link to a missing file. Navigation comes from the catalog's tags (`catalog/README.md`); this folder holds the hand-checked extras.

| File | What it holds | Rule |
|---|---|---|
| `situations.csv` | "Where to look first" on a topic page: situations in plain words, each with its `topic` (a coverage id) and a PDF page in a Tier 1 item. A row with a blank `item_id` and `pdf_page` is note-only: its checked note in `notes/` is the content (e.g. 09, radios, under C1). | Check every page against the PDF text and record that in `checked`. |
| `paths.csv` | Learning paths ("New to this? Read these in order"): a path is 2 to 4 steps, each a whole guide (or a PDF page already recorded in the catalog or `situations.csv`), with a one-line reason. Shown on its topic's page, as a card on the home page, and in search. A path with fewer than two steps on the drive is left out. | Each reason uses only what the guide's catalog notes say; give the check date in `checked`. `tests/test_catalog.py` checks items, topics and step numbers. |
| `numbers.csv` | Emergency phone numbers, shown on the first-aid topic page (S1) and on the printed card (`arc/site/card.html`) | Re-check at the source before each build: service-public.gouv.fr and centres-antipoison.net. |
| `notes/<order>_<name>.txt` | Checked text shown under a situation, e.g. the metric water doses | Shown on every build, under the first situation with that `order` in `situations.csv`. Cite the sources and the check date inside the note. An order no situation has stops the build. |
| `drafts/<order>_<name>.txt` | Text not checked yet | Same naming. Shown only on test builds (`assemble.py --allow-pending`), in a yellow "DRAFT" box. To publish one, check it and move it to `notes/`. |

The look (D17, 22 Nov 2026, "learning app"): `CSS` in `frontdoor.py`, one colour and line icon per subject (`ICONS`, `.s-<subject>`), the home page's quick ways in (`QUICK`), system fonts only, dark mode from the device's setting. Every page has a plain search form (no script) that opens `arc/site/search.html?q=...`.

Page rules (CLAUDE.md rule 4): self-contained pages (inline CSS), no JavaScript except two inline scripts: the search page's (it searches an index of the topics, guides, learning paths and first-aid situations written into the page; accents ignored; results built as text), and START-HERE's (phase 4c): it shows the launcher for this kind of computer and, when the library on this computer lists the arc's own collection, switches to it (`#stay` at the end of the address keeps the page and offers a link instead; it asks again every 3 seconds for about 20 minutes, so the page also switches once the library is started), no web fonts, relative links to files on the drive. The only absolute address is the full library on this computer, `http://127.0.0.1:8642`, for collections and searches; those links say they need the full library. A topic's search words (`coverage.csv` `search`) link to the library home with `?q=`, which runs the search after dropping any collection the server could not open. `tests/test_build.py` checks every link on every page, that nothing external is referenced, and that strict builds contain no draft text.
